# rforge Commands — the Dynamic Layer

> **The rule:** anything *computable* (status, dependency order, CRAN sequence,
> "what next") is **generated by rforge**, not hand-maintained in markdown. This
> hub holds the *prose* (roadmap, decisions, standards); rforge holds the
> live numbers. Run these from the ecosystem root:
>
> ```bash
> cd ~/projects/r-packages
> ```

## What replaced which static artifact

| Old hand-maintained markdown | Now generated by | What it shows |
|---|---|---|
| Per-package status table (versions, progress, blockers) | `/rforge:status` | Reads every package's `.STATUS`; one dashboard |
| Dependency diagram / DEPENDENCY-MAP tables | `/rforge:deps` | Topological order, reverse deps, cycles |
| "Implementation order" / CRAN submission sequence | `/rforge:release` | Dependency-ordered CRAN submission plan + readiness |
| "What should I do next?" decision blocks | `/rforge:next` | Ecosystem-aware next-task recommendation |
| Ad-hoc TODO capture | `/rforge:capture` / `:complete` | Task capture + completion with doc cascade |
| "Blast radius of this change" | `/rforge:impact` | What breaks if you change package X |
| Coordinated multi-package rollout | `/rforge:cascade` | Phased update plan across dependents |
| Whole-ecosystem rollup | `/rforge:thorough` | status + deps + health + CRAN order (2–5 min) |
| Quick snapshot | `/rforge:quick` | <10s ecosystem snapshot |

## Per-package source of truth

`/rforge:status` reads each package's **`.STATUS`** file (YAML header: `status`,
`priority`, `progress`, `last_updated`). Keep those current in each repo — that is
the single place per-package status is edited. Do **not** re-tabulate it here.

## What rforge does NOT do (stays in markdown / elsewhere)

- **Live CI/CD pass-fail badges** → the badge wall in `mediationverse/STATUS.md`.
- **Roadmap, design decisions, standards, specs** → this hub (`docs/`, `specs/`,
  `docs/design/`, `standards/`).
- **"What packages exist & where"** → [`../ECOSYSTEM-MANIFEST.yaml`](../ECOSYSTEM-MANIFEST.yaml).

## History

The 2025-12 proposal `archive/COORDINATION-HUB-BRAINSTORM.md` sketched bespoke
`medstatus` / `mednow` / `/ecosystem` scripts for exactly this. They were never
built because **rforge now provides all of it** — that brainstorm is archived as
superseded.
